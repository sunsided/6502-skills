# 65C02 — CMOS additions and changes vs NMOS 6502

The 65C02 (Apple IIe-enhanced, IIc; also many later systems) is a superset of
the NMOS 6502: all NMOS *documented* instructions behave the same, plus the
following. The undocumented NMOS opcodes are **not** available — they become
defined NOPs (see `undocumented.md`). Merlin enables 65C02 syntax with the `XC`
directive (one `XC` = 65C02; two = 65816).

## New instructions

| Instr | Operation | Flags | Modes added |
|-------|-----------|-------|-------------|
| BRA rel | branch always | — | relative |
| STZ | store $00 to memory | — | zp, zp,X, abs, abs,X |
| PHX / PHY | push X / Y | — | implied |
| PLX / PLY | pull X / Y | N Z | implied |
| INC A / DEC A | A <- A ± 1 | N Z | accumulator |
| TSB | M <- M \| A; Z <- (A & M)==0 | Z | zp, abs |
| TRB | M <- M & ~A; Z <- (A & M)==0 | Z | zp, abs |

`TSB`/`TRB` (test-and-set / test-and-reset bits) set or clear the mask bits of A
in memory and report, via Z, whether any of those bits were already set — a
read-modify-write atomic-ish bit operation common in I/O code.

## Rockwell / WDC bit instructions (present on Apple IIe/IIc 65C02)

| Instr | Operation | Flags |
|-------|-----------|-------|
| RMB0–RMB7 zp | clear bit n of the zero-page byte | — |
| SMB0–SMB7 zp | set bit n of the zero-page byte | — |
| BBR0–BBR7 zp,rel | branch if bit n of zp is 0 | — |
| BBS0–BBS7 zp,rel | branch if bit n of zp is 1 | — |

These are 5 (BBR/BBS) or 2 (RMB/SMB) byte instructions; the branch ones take a
zero-page address *and* a relative offset.

WDC-only: `WAI` (wait for interrupt) and `STP` (stop the clock) exist on WDC
W65C02S parts but are generally absent from the Apple-fitted versions.

## New addressing modes

- **`(zp)` zero-page indirect** (no index) for `ORA AND EOR ADC STA LDA CMP SBC`.
  This is `(zp),Y` with Y=0 — a direct pointer dereference without burning Y.
  Hugely common in 65C02 code; NMOS had to do `LDY #0` + `(zp),Y`.
- **`(abs,X)` absolute indexed indirect** for `JMP` — `JMP ($1234,X)`. Jump
  through a table of addresses indexed by X. (NMOS only had `JMP (abs)`.)
- **`BIT` gains** immediate (`BIT #imm`), `BIT zp,X`, and `BIT abs,X`. Note:
  `BIT #imm` affects **only Z** (it cannot meaningfully set N/V from an
  immediate the way memory `BIT` does).

## Bug fixes and behavior changes (matter when porting)

- **`JMP (abs)` page-boundary bug is fixed.** `JMP ($xxFF)` now reads the high
  byte correctly from the next page (costs one extra cycle).
- **Decimal mode sets N, V, Z correctly** after ADC/SBC (NMOS left them
  garbage). ADC/SBC in decimal mode take **one extra cycle** on the 65C02.
- **Read-modify-write absolute,X** does one fewer (dummy write → dummy read)
  bus cycle; timing differs slightly but result is the same.
- **A few opcodes gained a cycle**; consult a cycle-exact reference if timing
  matters.

When porting, the practical upshot: if the original is NMOS and relied on the
`JMP (ind)` bug or on garbage decimal flags, a 65C02 reimplementation behaves
differently. Confirm the target CPU before assuming.

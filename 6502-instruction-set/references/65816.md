# 65816 / 65802 — 16-bit additions vs 6502/65C02

The WDC 65C816 (Apple IIgs; the 65802 is the same core in a 6502 pinout)
extends the 65C02 to 16-bit registers and a 24-bit (16 MB) address space, while
booting in an **emulation mode** that is binary-compatible with the 6502. Almost
every porting mistake here comes from losing track of *mode* and *register
width*. Track them as you read.

## Emulation vs native mode — the E flag

- Power-on / RESET puts the CPU in **emulation mode (E=1)**: behaves like a
  65C02, registers effectively 8-bit, stack confined to page 1.
- Software switches to **native mode** with `CLC : XCE` (exchange carry and E).
  `SEC : XCE` returns to emulation. The E flag is "hidden" — you read/set it
  only via XCE through the carry.

## Register width — the M and X flags (native mode only)

In native mode two status bits choose register widths:

- **M flag** (status bit 5): 0 = 16-bit accumulator/memory, 1 = 8-bit.
- **X flag** (status bit 4): 0 = 16-bit X/Y, 1 = 8-bit index registers.

Set/clear them with `SEP #const` (set status bits) and `REP #const` (reset
status bits), e.g. `REP #$30` → 16-bit A and index; `SEP #$20` → 8-bit A.

**Critical for reading code:** the *length of an immediate operand depends on
the current M/X flags.* `LDA #$1234` assembles to 3 bytes when M=0 but
`LDA #$12` to 2 bytes when M=1 — the same mnemonic, different size. A
disassembler (or you) must track M/X to decode the byte stream correctly.
Merlin tracks this with the `MX` directive and `XC` (two `XC`s = 65816); a
wrong `MX` desynchronizes the whole listing.

In emulation mode M and X are forced to 1 (8-bit), and the high byte of the
index registers reads as 0.

## Wider registers and new registers

| Register | Width | Notes |
|----------|-------|-------|
| C = B:A  | 16    | A is the low half; B (hidden) the high half. `XBA` swaps them. |
| X, Y     | 8/16  | per X flag |
| S        | 16    | native-mode stack can be anywhere in bank 0 |
| D (DP)   | 16    | Direct Page register: relocatable "zero page" — direct-page addressing is `D + offset`, not fixed `$00xx` |
| DBR      | 8     | Data Bank register: default bank for absolute data accesses |
| PBR (K)  | 8     | Program Bank register: bank of the PC |

Because of D and DBR, a "zero page" or "absolute" access in 65816 source is not
necessarily at `$00xx`/`$00xxxx` — its physical bank/offset depends on D and
DBR at runtime.

## New instructions

| Instr | Operation |
|-------|-----------|
| REP / SEP #imm | reset / set status bits (used to flip M/X and others) |
| XCE | exchange C and E (enter/leave native mode) |
| MVN / MVP | block move negative/positive (src bank, dst bank operands; C = count-1; uses X,Y) |
| PEA / PEI / PER | push effective address / indirect / PC-relative — for building stack frames & position-independent code |
| PHB PLB / PHD PLD / PHK | push/pull data bank, direct page; push program bank |
| TCD TDC / TCS TSC | transfer C↔D, C↔S (16-bit) |
| TXY TYX | transfer X↔Y |
| XBA | swap the two bytes of C (A↔B) |
| BRL | branch always long (16-bit relative range) |
| JML / JSL / RTL | long (24-bit) jump / call / return — cross-bank |
| JSR (abs,X) | indexed indirect subroutine call |
| COP | software interrupt (coprocessor) via $FFF4 vector |
| WDM | reserved / no-op (acts as a 2-byte NOP) |
| STP / WAI | stop clock / wait for interrupt |

## New addressing modes

| Mode | Syntax | Meaning |
|------|--------|---------|
| Stack relative | `LDA d,S` | operand at `S + d` |
| Stack rel indirect indexed | `LDA (d,S),Y` | pointer at `S+d`, then +Y |
| Direct page indirect long | `LDA [d]` | 24-bit pointer at direct page d |
| DP indirect long indexed | `LDA [d],Y` | 24-bit pointer + Y |
| Absolute long | `LDA $123456` | full 24-bit address (ignores DBR) |
| Absolute long indexed | `LDA $123456,X` | + X |
| Block move | `MVN src,dst` | bank-to-bank copy |

## Porting checklist for 65816 source

1. Establish E, M, X state at every point — they are a hidden part of the
   instruction's meaning. A routine often does `REP #$30` on entry and assumes
   16-bit throughout; a callee might change them and forget to restore.
2. Note the bank registers (DBR/PBR) and the direct page (D) — addresses in the
   source are relative to these, not absolute.
3. 16-bit loads/stores wrap at 16 bits within a bank; they do **not** carry into
   the next bank (except long modes and block moves).
4. When in doubt, a IIgs routine that touches the toolbox or GS/OS is almost
   always native-mode 16-bit on entry.
